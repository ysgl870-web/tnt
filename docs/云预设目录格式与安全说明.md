# TNT 云预设目录格式与安全说明

作者：亦是光流。

## JSON 结构

最重要的兼容字段是 name 和 content。TNT 接受 JSON 数组，也接受对象中包含 presets、elements、data、list 或 items 数组的形式。示例文件：examples/cloud-presets.example.json。

每个条目可以包括：
- name：必填，人类可读的预设名；
- content：必填，文本/JSON/HEX 草稿内容，不会作为脚本执行；
- package_name：可选的应用包名或来源标签；
- description、tags、schema_version：可选扩展，旧导入器应忽略不认识的字段。

TNT 识别黑壳历史复合记录分隔符 *awa_pkg_name_pkg_content_split* 的简单记录，但只把解析结果作为数据。

## 发布建议

将 JSON 放在你自己控制的 HTTPS 静态托管地址（例如自己的站点或 GitHub Pages），然后在模块内手动输入最终 URL。不要提交 QQ Cookie、UIN、Token、签名、聊天记录或私密定位信息。公共目录只能包含适合公开分享的模板。

## 客户端规则

- 只有用户显式点击后才发起 HTTPS GET，不后台自动同步；
- 不跟随 HTTP 重定向，要求用户填写最终 URL；
- 不附加 QQ Cookie、Authorization 或本地配置；
- 限制响应大小，检查本机/私网主机；
- 先预览并勾选后导入本地；
- 不把 content 当作代码、脚本或协议发送指令执行；
- HTTPS 仅保护传输，不代表远端模板本身可信。

## 版本策略

未来目录可以增加 schema_version 与 updated_at；保持 name/content 兼容字段，额外字段采用可忽略扩展，以兼容较旧的 AWA/黑壳导入器。
